# Цель работы

Цель данной работы - получить представление о работе с учётными записями пользователей и группами пользователей в операционной системе типа Linux.

# Выполнение лабораторной работы

## Переключение учетных записей пользователей.

1. Определите, какую учётную запись пользователя вы используете, введя команду whoami. Выведите на экран более подробную информацию, используя команду id. В отчёте дайте пояснение по отображённой информации.

![Команды whoami, id](image/1.png){#fig:001 width=80%}

В результате ввода команды id мы получаем информацию: 
* uid (user id) - id пользователя, равный 1000
* gid (group id) – id группы, равный 1000)

2. Используйте команду su для переключения к учётной записи root. При запросе пароля введите пароль пользователя root. Наберите id. В отчёте дайте пояснение по отображённой информации. Вернитесь к учётной записи своего пользователя (su имя_пользователя) или воспользуйтесь комбинацией клавиш Ctrl + d или командой exit.

![Команды su, id, exit](image/2.png){#fig:002 width=80%}

В результате ввода команды id для root мы получаем информацию: 
* uid (user id) - id пользователя, равный 0
* gid (group id) – id группы, равный 0

3. Просмотрите в безопасном режиме файл /etc/sudoers, используя, например, sudo -i visudo. В отчёте поясните, почему для работы с файлом /etc/sudoers требуется использовать visudo, а не произвольный редактор. Убедитесь, что в открытом с помощью visudo файле присутствует строка %wheel ALL=(ALL) ALL. В отчёте поясните, что это означает и для чего нужна группа wheel.

![Работа с файлом /etc/sudoers](image/3.png){#fig:003 width=80%}

Для работы с файлом /etc/sudoers требуется использовать именно редактор visudo, а не произвольный редактор, по двум основным причинам:
* visudo - это не просто текстовый редактор, а специальная утилита, которая после завершения редактирования проверяет файл на наличие синтаксических ошибок (что позволяет избежать полной блокировки выполнения команд sudo для всех пользователей, включая root)
* visudo гарантирует, что файл /etc/sudoers всегда будет целостным, тк он сохраняет итоговый файл только в том случае, если проверка прошла успешно (что исключает ситуацию "полузаписанного" или отсутствующего конфигурационного файла).

Группа wheel в Linux — это специальная группа, членам которой предоставляется право получать права суперпользователя (root) с помощью команды sudo. Эта группа нужна для безопасного администрирования системы, отслеживания действий каждого отдельного пользователя (через журнал), а так же для гибкости управления доступом.

4. Создайте пользователя alice, входящего в группу wheel:
sudo -i useradd -G wheel alice. Убедитесь, что пользователь alice добавлен в группу wheel, введя id alice.

![Создание пользователя alice](image/4.png){#fig:004 width=80%}

5. Задайте пароль для пользователя alice, набрав sudo -i passwd alice.

![Создание пароля для alice](image/5.png){#fig:005 width=80%}

6. Переключитесь на учётную запись пользователя alice: su alice. Создайте пользователя bob: sudo useradd bob. Введите пароль при запросе. 

![Создание пользователя bob](image/6.png){#fig:006 width=80%}

7. Проверьте, что пользователь bob создан. Установите пароль для пользователя bob: sudo passwd bob. Просмотрите, в какие группы входит пользователь bob: id bob. 

![Создание пароля для bob](image/7.png){#fig:007 width=80%}

Пользователь bob является членом только своей собственной первичной группы (bob).

## Создание учетных записей пользователей.

Например, найдите параметр CREATE_HOME и убедитесь, что он установлен в значение yes. Также установите параметр USERGROUPS_ENAB no.

5. Посмотрите и прокомментируйте информацию о пользователе carol, проверьте, в какую первоначальную группу входит пользователь carol; также убедитесь, что каталоги Pictures и Documents были созданы в домашнем каталоге пользователя carol:

![Информация о пользователе carol](image/13.png){#fig:013 width=80%}


* gid=100(users) означает, что первичной (основной) группой пользователя carol является группа с id 100 и именем users.
* группы=100(users): обозначает список всех групп, в которые входит пользователь. Carol состоит только в одной группе — users, и не входит ни в какие другие группы (например, sudo, wheel, audio и т.д.). То есть первичной и единственной группой для carol является группа users.

6. Переключитесь в терминале на учётную запись пользователя alice: su alice. Поясните в отчёте строку записи о пароле пользователя carol в файле /etc/shadow: sudo cat /etc/shadow | grep carol. Измените свойства пароля пользователя carol следующим образом: sudo passwd -n 30 -w 3 -x 90 carol. В этой записи срок действия пароля истекает через 90 дней (-x 90). За три дня до истечения срока действия пользователь получит предупреждение (-w 3). Пароль должен использоваться как минимум за 30 дней (-n 30) до того, как его можно будет изменить. Убедитесь в изменении в строке с данными о пароле пользователя carol в файле /etc/shadow: sudo cat /etc/shadow | grep carol.

В строку записи входит информация о логине пользователя (carol), зашифрованный пароль пользователя, а так же срок действия пароля от учетной пользователя.

# Контрольные вопросы

1. При помощи каких команд можно получить информацию о номере (идентификаторе), назначенном пользователю Linux, о группах, в которые включён пользователь?
- Команда "id".

2. Какой UID имеет пользователь root? При помощи какой команды можно узнать UID пользователя? Приведите примеры.
- Пользователь root имеет UID 0. Узнать UID можно командой "id -u [username]". Пример: "id -u root" (вернет 0) или "id -u" (покажет UID текущего пользователя).

3. В чём состоит различие между командами "su" и "sudo"?
- "su" переключает пользователя и требует пароля целевого пользователя (обычно root). "sudo" выполняет одну команду с привилегиями root и требует пароля текущего пользователя, если он есть в группе sudo/sudoers.

4. В каком конфигурационном файле определяются параметры sudo?
- Параметры sudo определяются в конфигурационном файле "/etc/sudoers".

5. Какую команду следует использовать для безопасного изменения конфигурации sudo?
- Для безопасного изменения конфигурации sudo следует использовать команду "sudo visudo".

6. Если вы хотите предоставить пользователю доступ ко всем командам администрирования системы через sudo, членом какой группы он должен быть?
- Пользователь должен быть членом группы "sudo" (в Debian/Ubuntu) или "wheel" (в RHEL/CentOS/Fedora).

7. Какие файлы/каталоги можно использовать для определения параметров, которые будут использоваться при создании учётных записей пользователей? Приведите примеры настроек.
- Файлы "/etc/login.defs" (настройки umask, длительности пароля) и "/etc/default/useradd" (путь к оболочке по умолчанию, группа по умолчанию). Пример: "UMASK 022" в "/etc/login.defs".

8. Где хранится информация о первичной и дополнительных группах пользователей ОС типа Linux? В отчёте приведите пояснение таких записей для пользователя alice.
- Информация хранится в файле "/etc/group". Для пользователя alice запись "sudo:x:27:alice" означает, что alice является членом дополнительной группы "sudo" (GID 27).

9. Какие команды вы можете использовать для изменения информации о пароле пользователя (например о сроке действия пароля)?
- Команду "chage". Пример: "sudo chage -M 90 -E 2024-12-31 alice" (установить максимальный возраст пароля 90 дней и срок его действия до 31 декабря 2024 года).

10. Какую команду следует использовать для прямого изменения информации в файле /etc/group и почему?
- Команду "vigr". Она блокирует файл от одновременного редактирования и проверяет его целостность, что предотвращает повреждение данных.
